# Temple Builder studio upgrade — October 23, 2026

## Baseline and preservation

Started from main `b6b2c7bb347803601efe241bb2fdcd588c5690db`. Reused the existing camera rewrite work from `ea7e26e` and `be00ef3` on the camera-controller-rewrite branch, then improved that single controller. Existing architectural generation, ownership IDs, add/remove levels, deletion undo, six templates, twenty footprints, walls, gates, towers, floors, columns, roofs, doors, windows, trim, stairs, statues, landscaping and local saving remain. No saved-data schema migration is introduced. No builder categories or user assets are intentionally removed.

## Changes

### Navigation and touch

- One camera controller owns position, target, spherical orbit, projection, framing and ground limits. The legacy camera refs/helpers have been removed from the preview.
- Actual toolbar height determines the unobstructed viewport. Fit uses that usable height, including in landscape.
- Center Temple refreshes the selected building's bounds without changing camera framing merely because selection changes.
- Whole Site includes perimeter walls and user-placed site objects; Front and Plan views provide useful architectural angles.
- Ground limits apply to pan and zoom as well as orbit. Rendering near/far atmosphere adjusts to camera distance so large scenes do not disappear into fog.
- Short damping settles camera motion, honoring reduced-motion preferences, then rendering stops when idle.
- Drag intent stays latched after crossing its threshold, so returning to the start cannot become a tap. Extra fingers immediately cancel object movement. Three-finger transitions pause/rebase correctly. Pointer cancellation/lost capture cannot select.
- Middle/right button pan uses the held-button bitmask. Two-finger pan uses the real camera projection scale. Site pieces and statues retain the ground grab offset when dragged.
- Pending blue buildings can be dragged before confirmation. Move is accessible for all object categories; Done exits Move mode.

### Rendering and performance

- Three.js upgraded from `0.170.0` to published `0.186.1`, with matching `@types/three` `0.186.0`. Adapted soft shadows to supported PCFShadowMap. Next.js patch updated from `15.3.8` to `15.3.9`; React remains unchanged. Added a dependency lockfile.
- On-demand frame scheduling coalesces renders to display frames. Shadow maps refresh when scene/light changes, rather than on every orbit frame.
- Unchanged building geometry is cached by persistent level ID and geometry inputs. Moving a building updates transforms instead of disposing/rebuilding its meshes. Changed/deleted levels dispose their own resources.
- Shell materials are reused per level. Compatible shell meshes are merged in local space; interactive attachments retain individual identity. A geometry test batches 100 shell meshes into one while preserving bounds to Float32 tolerance and retaining an independent window.
- Environment lighting uses PMREM and RoomEnvironment with no HDR downloads, giving PBR materials reflections. Rebalanced sunlight, hemisphere/fill light, exposure and twilight lighting.
- Sky gradients, a single low-poly distant ridgeline, larger terrain and a subtle optional grid add depth. Balanced/detail pixel-ratio modes cap rendering cost.
- Ghost replacement releases superseded materials. Stateless statue highlighting no longer rebuilds geometry. Context failures show a recovery prompt.

### Selection and architectural corrections

- Window casings/mullions, door surrounds/porticoes, column capitals/rings/fluting, arch legs, trim decoration, stairs and pediments receive their attachment's selection/movement identity.
- Roofs generated by the shared roof builder select the roof editor.
- Perimeter generation accounts for translated and rotated building extents, centers on the actual site, and encloses those bounds for rectangle, circle, octagon and star styles.
- Perimeter gates occupy a real gap in the chosen front edge. Corrected upside-down semicircular arches/pediments.
- Upper-level patio inference is limited to levels with the same building ownership ID.

### Studio interface

- Brass/navy studio header, scene counts, responsive compact view tools, visible local-save status and clearer Move state.
- Foundation plan drawings and six architectural template thumbnails replace generic empty preview boxes.
- Direct stair/roof entry points, usable Studio panel and no placeholder footer beneath populated menus.
- Download a JSON design copy and capture a PNG of the current 3D view. JSON is a backup/export; this change does not add an import interface.
- Keyboard focus treatment, accessible view labels and reduced-motion handling.

## Verification

- `npm run typecheck` and `npm run build` pass on the updated engine.
- `npm test`: 13 checks covering production pointer handlers, framing in portrait/landscape, ground limits, shell batching and rotated perimeter enclosure.
- `npm run verify:browser`: scripted Chromium/SwiftShader checks of placement/confirmation/local save; orbit without object movement; deliberate drag with identical mesh UUIDs before/after; emulated two-finger pinch; owned stacked levels; selection without camera reset; landscape/view presets; JSON and PNG downloads; reload restoration; all six complete templates; and a scene with walls, roof, stairs, columns, doors, windows, arches, trim, pediments, statue and fountain.
- Browser test also checks actual attachment submesh tags and absence of JavaScript/WebGL console errors. Screenshots are inspected, including mobile portrait, mobile landscape and a larger desktop twilight view.
- `scripts/verify-studio.cjs` accepts PLAYWRIGHT_MODULE, CHROMIUM_PATH and QA_OUTPUT for rerunning in a browser-capable environment. Playwright/Chromium are test tooling, not production dependencies.
- Physical Android/iPhone GPU performance, every saved legacy design and every possible combination of geometry have not been tested. Browser emulation is not a physical-device guarantee. No measured phone FPS claim is made.

## Research and technology choice

Checked current primary documentation and package metadata rather than treating novelty alone as a benefit:

- Three.js r186 release/migration notes: https://github.com/mrdoob/three.js/releases/tag/r186
- PMREM: https://threejs.org/docs/pages/PMREMGenerator.html
- RoomEnvironment: https://threejs.org/docs/pages/RoomEnvironment.html
- OrbitControls behavior/reference: https://threejs.org/docs/pages/OrbitControls.html
- WebGPURenderer and its backend fallback: https://threejs.org/docs/pages/WebGPURenderer.html
- WebGPU browser support: https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API
- Pointer cancellation: https://developer.mozilla.org/en-US/docs/Web/API/Element/pointercancel_event

The renderer stays on WebGL2 for this release. WebGPU was evaluated, but migrating rendering/shaders and validating fallback across phones is a separate compatibility project. Current Three.js, PBR environment lighting, batching, geometry reuse and on-demand rendering deliver concrete improvements within the existing builder. This work does not claim to have visited every 3D website, added photogrammetry assets, or achieved photorealism.

## Known boundaries

- True openings/UV scale and certain complex footprint attachments remain inherited architectural limitations; not every named style has unique production asset geometry.
- The finite terrain can still be exceeded by unbounded horizontal placement/pan. Whole Site and Center Temple recover framing.
- Camera picks the selected building for Center Temple; Whole Site frames the entire editable site. Selection itself deliberately does not move the camera.
- One global perimeter still belongs to the site rather than a per-building wall ownership model. Free-standing site objects remain independent.
- Old draft PR #1 is not merged wholesale; its relevant gesture fixes have been reapplied to the newer camera architecture.
